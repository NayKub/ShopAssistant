PROJECT OVERVIEW
-----------------
ShopAssistant is a full-stack web application for retail operations management. It provides basic tools for inventory management, sales processing, and business analytics.

Currently Implemented Features:
- Product inventory management (CRUD operations)
- Category management system
- Shopping cart and checkout functionality
- Sales analytics dashboard
- User authentication (register/login)
- Profile and store settings management
- Image upload for products
- Theme switching (light/dark mode)
- Basic restock functionality

SYSTEM ARCHITECTURE
-------------------
The application follows a simple client-server architecture:

1. FRONTEND (React SPA)
   - Single-page application with view-based routing
   - Component-based React architecture
   - Context API for theme management
   - Local storage for authentication tokens
   - Vite for development and building

2. BACKEND (Node.js/Express)
   - Express.js REST API server
   - JWT-based authentication
   - MongoDB database connection
   - File upload handling with Multer
   - CORS enabled for cross-origin requests

DEVELOPMENT ENVIRONMENT SETUP
------------------------------

PREREQUISITES:
- Node.js version 16.0.0 or higher
- npm version 8.0.0 or higher
- Git version control system
- MongoDB database (cloud or local)
- Modern web browser

INITIAL SETUP:
1. Clone the repository:
   git clone <repository-url>
   cd ShopAssistant

2. Install frontend dependencies:
   cd client
   npm install

3. Install backend dependencies:
   cd ../server
   npm install

ENVIRONMENT CONFIGURATION:
Backend (server/.env):
- Configure MongoDB connection string
- Set JWT secret key
- Set server port (default: 3000)

Frontend:
- No environment file needed for basic setup
- API calls are configured to localhost:3000

DEVELOPMENT SERVERS:
1. Start backend server:
   cd server
   npm start
   # Runs on http://localhost:3000 with nodemon

2. Start frontend development server:
   cd client
   npm run dev
   # Runs on http://localhost:5173

AVAILABLE NPM SCRIPTS:

Frontend (client/):
- npm run dev - Start development server
- npm run build - Create production build  
- npm run preview - Preview production build
- npm run lint - Run ESLint

Backend (server/):
- npm start - Start development server with nodemon
- npm run server - Alternative start command

API DOCUMENTATION
-----------------
Base URL: http://localhost:3000/api

AUTHENTICATION ENDPOINTS:
POST /api/auth/register - Register new user
POST /api/auth/login - User login

PRODUCT ENDPOINTS:
GET /api/products - Get all products (requires auth)
POST /api/products - Create product with image upload (requires auth)
GET /api/products/:id - Get specific product (requires auth)
PUT /api/products/:id - Update product with optional image (requires auth)
POST /api/products/restock/:id - Restock product (requires auth)
DELETE /api/products/permanent/:id - Delete product permanently (requires auth)

CATEGORY ENDPOINTS:
GET /api/categories - Get all categories (requires auth)
POST /api/categories - Create new category (requires auth) 
DELETE /api/categories/:id - Delete category (requires auth)

SALES ENDPOINTS:
POST /api/checkout - Process sale/checkout (requires auth)

ANALYTICS ENDPOINTS:
GET /api/analytics - Get main analytics data (requires auth)
GET /api/analytics/daily - Get daily sales data (requires auth)
GET /api/analytics/products - Get product performance data (requires auth)  
GET /api/analytics/categories - Get category performance data (requires auth)

SETTINGS ENDPOINTS:
GET /api/settings/profile - Get user profile (requires auth)
PUT /api/settings/profile - Update user profile (requires auth)
PUT /api/settings/profile-image - Update profile image (requires auth)

STORE ENDPOINTS:
GET /api/store/info - Get store information (requires auth)

Authentication:
All protected endpoints require Bearer token in Authorization header:
Authorization: Bearer <jwt-token>

File Upload:
Image uploads supported for products and profile pictures
Max file size: 5MB
Supported formats: JPEG, JPG, PNG, GIF

AUTHENTICATION SYSTEM
----------------------
The application uses JWT-based authentication:

Token Storage:
- JWT tokens stored in localStorage as 'userToken'
- Store ID stored as 'storeId' for multi-store support

Authentication Flow:
1. User submits login credentials
2. Server validates and returns JWT token
3. Token stored in localStorage  
4. Token sent in Authorization header for protected requests
5. Server validates token on protected endpoints

Route Protection:
- checkAuthStatus() function verifies token existence
- Redirects unauthenticated users to login
- Protected components check authentication status

Token Management:
- Logout clears tokens from localStorage
- No automatic token refresh implemented
- No session timeout handling

DEPLOYMENT INSTRUCTIONS
-----------------------

PRODUCTION BUILD:
1. Build frontend:
   cd client
   npm run build
   # Creates dist/ directory with production files

2. Backend configuration:
   - Set up MongoDB connection (Atlas recommended)
   - Configure JWT secret key
   - Set production environment variables
   - Configure file upload directory

3. Server deployment:
   - Deploy backend to hosting service (Heroku, Railway, etc.)
   - Deploy frontend build files to CDN or static hosting
   - Configure CORS for production domain

Environment Variables (Production):
- MONGODB_URI - Database connection string
- JWT_SECRET - Secret key for token signing  
- PORT - Server port (default 3000)
- NODE_ENV - Set to "production"

Static File Serving:
- Backend serves uploaded images from public/uploads/
- Frontend build files can be served by backend or separate CDN
